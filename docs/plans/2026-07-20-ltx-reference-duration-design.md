# LTX 跟随参考视频时长设计

## 目标

LTX 内容记录继续关联“人设”，只使用“参考视频链接”作为输入。Worker 自动解析飞书 URL/Markdown 链接、下载参考视频、检测时长并写入“视频时长”，最终成片时长与参考视频一致，不再固定为 30 秒。

## 方案

LTX 单次仍固定生成 5 秒。Worker 按 `ceil(参考视频时长 / 5)` 计算片段数，在参考视频时间线上提取 `片段数 + 1` 张边界帧，并要求 Kimi 返回相同数量的分段提示词。全部片段完成后，FFmpeg 先统一编码并拼接，再按参考视频时长精确裁切最后一段。这样既不拉伸视频，也不会用黑帧补齐。

当前短视频工作流支持最长 60 秒参考视频；超过 60 秒时明确失败，不会意外提交大量付费片段任务。

“视频时长”是 Worker 检测结果，不作为用户手工控制生成长度的参数。任务恢复时同时使用“视频时长”和已提交任务数量，确保 Worker 重启后仍能按正确长度合成。

## 数据与错误处理

- “人设”保留为与人设管理表的关联字段。
- 只读取并下载“参考视频链接”；空值或非 HTTP(S) 地址直接给出明确错误。
- “生成供应商”保留并由 Worker 自动回填。
- 无法检测时长、Kimi 返回的提示词数量不匹配、任务数量不完整时，记录进入失败状态并保留明确原因。
- 旧任务若已有任务 ID 和时长，按动态规则恢复；缺少时长的旧任务会提示重新触发，避免错误合成。

## 验证

单元测试覆盖动态片段数、动态边界帧、动态提示词数量、可变任务数量，以及按参考时长裁切的 FFmpeg 参数。完整测试后回读飞书字段、历史人设关联、参考视频附件、视频时长和供应商。
