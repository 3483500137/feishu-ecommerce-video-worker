# ADR-0001：接入API一行一个模型并使用本机 DPAPI 凭据

## 状态

Accepted

## 背景

每位部署者拥有独立的飞书多维表和本地 Worker，需要接入小云雀、Kimi/其他兼容模型及视频中转站。飞书需要提供逐条任务选择模型的能力，但不允许按模型拆分表，也不能因为分享或导出多维表而泄露 API 密钥。

## 决策

“接入API”表一条记录表示一个可选模型，并保存协议、接口地址、能力、默认用途和本机密钥别名。业务表通过关联字段选择模型。

密钥通过仅监听本机的配置页导入，使用 Windows DPAPI 加密保存在本地，不写入飞书。Worker 通过协议适配器统一调用 Chat Completions、Videos 和 XYQ Skill。

## 结果

### 正面

- 不增加模型表即可获得可验证的模型选择关系。
- 密钥不会随飞书分享、导出或日志泄露。
- 新模型通常只需增加接入记录，不需要增加内容表。
- 单个供应商失效不会阻止其他供应商任务。

### 负面

- 同一接口的多个模型会在“接入API”中占多行。
- DPAPI 密文与 Windows 用户绑定，换机后需要重新导入。
- 不同视频接口仍需要明确的协议适配器，不能只靠模型名称猜测参数。

### 中性

- 迁移期同时支持旧环境变量和新凭据库。
- 配置密钥需要离开飞书进入本机页面，日常选模型和触发任务仍在飞书完成。

## 备选方案

### 一行一个供应商，模型列表存文本

未采用。飞书无法可靠限制模型与接口的组合，任务记录还需要额外的模型ID字段。

### Worker按能力自动选择模型

未采用。无法满足逐条任务指定模型，并可能产生不可见的收费模型切换。

### 飞书保存密钥明文或可逆密文

未采用。分享、导出、权限配置错误和审计日志都会放大密钥泄露风险。
